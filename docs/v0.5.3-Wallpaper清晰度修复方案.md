# v0.5.3 Wallpaper 壁纸清晰度修复方案

## 问题与范围

v0.5.2 对 `project.file` 是独立图片的壁纸使用原图，但 Scene 壁纸的 `project.file` 通常是 `scene.json`。安装的 Workshop 项目通常只包含 `scene.pkg` 和小尺寸预览图，因此当前会把预览图铺满应用窗口，明显放大模糊。Wallpapers 的设置缩略图始终是预览图，也容易让用户误以为实际背景同样使用缩略图。

本次针对源选择和质量提示修复，不修改用户背景文件，不解包、解析或执行 `scene.pkg`。

## 实施方案

1. 保持 `project.file` 指向的独立 PNG/JPG/WebP 为最高优先级原图。
2. 对没有独立图片入口的项目，只在项目根目录及常见素材目录中查找名称明确表示背景的普通图片文件；文件必须通过现有项目路径白名单校验，尺寸需能读取且至少达到 1280×720（横竖屏均可）。只在比预览图清晰时采用，避免误选图标、纹理和小缩略图。
3. 仅剩预览图时继续使用预览，但读取预览/背景像素尺寸并在列表和选中项上标明“仅预览图”和分辨率，说明全屏放大后的模糊来自源图尺寸。
4. 视频壁纸保持原 MP4/WebM 播放；静止/减少动态效果或播放失败时使用当前可用的最佳静态背景图，无独立素材时才回退预览图。
5. 修正 Release 打包脚本：成功生成 ZIP 后移除它本轮创建的解压暂存目录，使 `release` 中每个新版本只留下一个安装 ZIP。
6. 将 v0.5.1 两个历史解压暂存目录移入 Windows 回收站，保留标准名的唯一 v0.5.1 安装 ZIP。

## 版本与验收

- 源码及清单版本递增为 v0.5.3。
- 运行 lint 和构建，不执行自动测试（本轮用户未要求测试）。
- 生成一个标准名 v0.5.3 安装 ZIP，核对外层 MANIFEST、归档版本和客户端哈希。
- 按用户既有升级要求安装到本机 `web` profile，并回读双 manifest、客户端哈希和 lockfile 包版本。
- 真实 Harness 页面视觉验收与正式 GitHub Release 不在本次范围内。

## 已知边界

Wallpaper Engine 官方说明 Workshop 动图预览受 256×256 像素限制；Scene 项目的原始源文件通常不随下载包提供。若本地 Scene 项目只有 `.pkg` 和预览图，插件无法仅靠放大或改压缩参数恢复场景原始画质。需要高清静态背景时，可在 Wallpaper Engine 中渲染/截取匹配显示器分辨率的静态图后导入；要在插件中保持 Scene 动画且高清，则需要另行设计受支持的渲染集成。
