# v0.5.7 本地壁纸图片格式误判修复方案

> **历史版本档案：** 本文记录 v0.5.7 的格式识别修复与当时的截图验收边界；当前版本为 v1.0.1，Desktop 安装及验收状态见 [项目 README](../README.md)。

## 现象与原因

用户在文件选择器中选中以 `.png` 结尾的图片后，设置面板显示“请选择 PNG、JPG 或 WebP 图片”。当前校验同时要求文件扩展名与文件头签名对应：例如，`.png` 文件只有在内容签名也被识别为 PNG 时才通过。文件名后缀不能证明实际编码；如果图片内容为另一种受支持格式但后缀不一致，就会被误拒绝。截图中的原始图片文件目前不在工作区可读路径，暂不能确认该文件的实际签名。

## 实施方案

1. 以 PNG、JPEG、WebP 文件头签名识别实际图片格式，不再要求签名与文件名扩展名一致；保留 64 MiB 上限与 8192×8192 尺寸限制。
2. 不支持或签名损坏时，提示实际内容不属于可用格式，并提示检查文件内容与扩展名，避免继续只显示“请选择 PNG…”的泛化错误。
3. 将双 manifest、README、INSTALL、源码与唯一离线安装 ZIP 更新为 0.5.7；不升级本机 DSH profile，也不发布 GitHub Release。

## 验收边界

- `npm run lint` 与 `npm run build` 通过；不运行自动测试。
- 检查 bundle 与两个 manifest 版本一致，安装 ZIP 内文件清单与哈希一致，且每版只保留一个安装 ZIP。
- 未取得用户选中的原图字节，因此无法确认该文件自身是否为有效 PNG/JPG/WebP；只有在真实页面用该文件重新选择并应用，才能完成针对该文件的人工验收。
