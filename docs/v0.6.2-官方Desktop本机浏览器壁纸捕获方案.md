## 目标

让用户继续使用官方 DeepSeek Harness，通过普通插件覆盖 Wallpaper Engine 的 Image、Video、Scene、Web、Application 五种类型，并只分发一个便于分享的插件安装 ZIP。

## 类型映射

| 类型 | 插件来源 | 额外步骤 |
| --- | --- | --- |
| Image | 项目原始图片候选；无可靠原图时明确回退 preview | 无 |
| Video | 项目原始 MP4/WebM，通过 Host Range 接口读取 | 无 |
| Scene | Wallpaper Engine 具名窗口的实时画面 | 默认浏览器选择该窗口 |
| Web | Wallpaper Engine 运行项目后的实时画面 | 默认浏览器选择该窗口 |
| Application | Wallpaper Engine 运行项目后的实时画面；若清单未写 `type`，按 `.exe` 项目文件识别 | 插件内勾选可信确认，再由浏览器选择窗口 |

Scene/Web/Application 的窗口选择器不嵌在 DSH Electron 中。插件 Host 调用固定参数的官方 WPE CLI 打开只属于本会话的具名窗口，并用 Windows 默认 URL handler 打开本机配对页。Scene 优先使用 `project.json`；若清单缺失、结构损坏或 Scene 入口文件不存在，仅当项目根目录存在唯一 `.pkg` 和 preview 时使用官方 CLI 直接打开 `.pkg`，不解包。Web 使用项目入口 HTML，Application 在验证项目 `.exe` 后由 WPE 加载项目 `project.json`。配对页必须是顶层页面；用户点击按钮后，Chrome/Edge 调用标准 `getDisplayMedia` 并请求 `cursor: 'never'`。用户选中窗口后，捕获轨道经 WebRTC 发送回 DSH 插件 Renderer，由页面背景层或可拖动设置面板播放。浏览器可能忽略鼠标隐藏请求，系统鼠标仍可能可见。Wallpaper 列表、搜索、候选和应用操作位于独立选择页，不嵌在设置面板中。

## 本机数据流

```text
官方 DSH Desktop renderer（dsh-app://app）
    │ 通过 Desktop 转发到本机 Host 的插件 API
    ▼
插件 Host ──固定参数──> Wallpaper Engine CLI ──> DSH Balance 随机具名窗口
    │
    └──webServer.port──> http://127.0.0.1:<port>/... 配对页 ──> Chrome/Edge
                                                             │ 用户选择具名 WPE 窗口
                                                             └──RTCPeerConnection──> 插件 Renderer 背景层
```

Desktop 主界面来源 `dsh-app://app` 是 Electron 自定义协议，不是 localhost HTTP 来源。官方 Desktop authenticated forwarder 将请求转发至本机 Host 时删除 `Host`、`Origin`、`Sec-Fetch-Site`，所以 Renderer 会为 Wallpaper 渲染 API 附带仅在官方 Desktop 页面生成的来源标记；Host 校验该标记并验证仍可用的 loopback Host/peer。兼容旧版 Desktop 的 `app://dsh`。Host 创建系统浏览器配对页时必须改用本机 WebServer 的 loopback 地址。Desktop 官方说明列出本机 Host 端口（默认 `19387`，可配置）；实现读取运行中的 `webServer.port`，不硬编码默认端口。普通 Web localhost 模式则继续从原始 loopback 来源打开配对页。

本机配对页通过随机 UUID 会话路径读取短期 offer，并回传 answer。Desktop Renderer 与 Chrome/Edge 捕获页分别绑定到经标记识别的 Desktop 来源和 `http://127.0.0.1:<port>` 两个角色来源；信令读写按 peer 角色校验。缺少 Origin 的浏览器读取只允许匹配配对页 Host 且 TCP 对端为 loopback 的请求。媒体轨直接通过 WebRTC 同机连接，不经过插件 Host 媒体转码或云端服务。配对页设置 no-store、同源脚本和禁止嵌入的 CSP，不包含 DeepSeek API Key。连接后配对页每 30 秒发送本机会话心跳；关闭配对页或停止共享会请求关闭该会话的具名 WPE 窗口，Host 定时回收过期会话，关闭 DSH 插件时也会清理活动窗口。

## 校验和安全边界

- Host 仅接受 numeric Workshop ID、注册库路径对应的库标识、Scene/Web/Application 固定类型和受限宽高；重新读取 `project.json`，并重验 Scene 项目清单或直接 `.pkg`、Web 入口 HTML、Application EXE 位于已发现 Workshop 根目录中。`.pkg` 回退限定唯一的根目录文件，并与当前会话的清单记录一致。
- WPE 必须已安装并正在运行；Host 只使用已安装 Steam 库中的 `wallpaper64.exe` / `wallpaper32.exe`，固定参数数组运行 `execFile`，`shell: false`。
- 只允许 `dsh-app://app`、兼容旧版的 `app://dsh` 来源标记或本机 loopback HTTP 来源启动本机文件和应用；不接受其他自定义协议。Desktop renderer 标记会拒绝明确的跨站请求，并在请求仍携带 Host/peer 信息时校验 loopback。Desktop 的捕获页与信令只经本机 loopback WebServer 端口开放，远程 Web Host 不支持。
- 插件主页面只检查 `RTCPeerConnection` 接收能力，不以其 `isSecureContext` 判定 Harness 是否本机运行；Chromium 安全上下文限制由 localhost 捕获页在请求窗口共享时检查。
- 插件不列出或自动授权任何屏幕/窗口来源。浏览器要求用户点击并选取单个窗口。标准捕获轨道不提供可验证的窗口标题/PID，插件无法防止用户误选其他窗口；配对页明确显示目标窗口名并提示不要共享整个屏幕。
- 捕获请求仅在 `getDisplayMedia()` 的 video 约束中设置 `cursor: 'never'`，不对轨道应用精确约束或检查浏览器实际设置/能力。浏览器可能忽略该提示，因此系统鼠标仍可能出现在共享画面中；壁纸内容本身绘制/烘焙的指针也不会被移除。[W3C Screen Capture 约束定义](https://www.w3.org/TR/screen-capture/#constrainable-properties)、[Chromium cursor 约束实现讨论](https://groups.google.com/a/chromium.org/g/feature-media-reviews/c/cOuS8x8rMZY)
- Application 可运行项目内容，插件必须要求用户每次明确勾选信任确认。只对用户信任的项目启用。
- 当前信令在同源随机会话路径中传递。WebRTC 没有配置 STUN/TURN；主机防火墙或浏览器策略可能阻止同机连接。

## 支持条件和失败处理

需要 Windows 本机官方 Desktop、Wallpaper Engine 已启动、已安装壁纸项目、默认最新版 Chrome/Edge，以及运行中的本机 Host WebServer。Desktop 下捕获页使用 Host 的 `webServer.port`，不需要 `dsh-app://` 由 Chrome/Edge 打开。浏览器拒绝捕获、用户取消、误选窗口、ICE 连接失败或 WPE 不支持该项目时，当前已应用背景保持不变，并清理新窗口。Image/Video 与静态 preview 回退不依赖本机捕获。

用户打开设置且页面/面板使用同一来源时，两处共用全窗口媒体/捕获层并保持动态；来源不同时页面层暂停，面板仍按自己的来源显示。切换或还原背景、停止共享、关闭捕获页、插件卸载会停止相关媒体轨并请求关闭对应 WPE 具名窗口。WPE 窗口或默认浏览器启动失败会返回不同错误并清理本轮窗口。捕获页失联后 Host 最迟在会话超时清理该窗口。DSH profile 重启后，保存的渲染模式需要用户重新点击应用并重新批准浏览器窗口捕获。
