# v0.4.5 真实使用问题修复方案

> **v1.0.1 当前行为：** 系统“减少动态效果”影响余额滚动、桌宠动画和本地导入视频；Wallpaper Engine Video 不受该开关影响；页面隐藏时页面层背景暂停，设置打开时同一精确来源共用单层并继续播放，来源不同时暂停页面层视频。本文记录 v0.4.5 的修复和验收；当前边界见 [v1.0.1 Desktop 兼容说明](v1.0.1-Desktop兼容说明.md)。

状态：已实施并完成主要隔离回归、Chrome `taoyiii` 受控 Harness 验收和真实 `web` profile 安装；真实安装已回读两份 manifest 为 0.4.5。真实 DeepSeek API、少数用户环境分支和 GitHub Release 仍未完成。

日期：2026-09-23

用户反馈：

- 真实 Harness 中的余额变化仍然没有类似手机闹钟/计时器选择项的竖向滚动。
- 没有可用余额时，主胶囊仍显示旧金额，只有鼠标悬停后才看到“DeepSeek 返回了无法识别的余额数据”。
- 同一份 v0.4.4 分享包在本机可以打开，在对方电脑双击安装器却直接闪退；对方环境还缺少 pnpm。

参考材料：只读核查 `D:\deepseek Harness\dsh-balance-roll-diagnosis`，并与当前工作区源码、v0.4.4 `.tgz` 及分享 ZIP 交叉比对。参考目录未被修改。

## 1. 结论摘要

v0.4.4 不应继续作为对外验收包。下一次实施使用新版本 `0.4.5`，不覆盖或重复分发同名 v0.4.4 ZIP。

| 问题 | 已确认事实 | 下一版决定 |
| --- | --- | --- |
| 滚轮仍不可见 | `src/client.js` 在轨道开始移到终点的 `end` 阶段，就把上排旧金额换成了新金额；下排本来也是新金额，因此实际过渡的是“新值 → 同一个新值” | 重做为明确的双排滚筒：整个旧余额向上移出，整个新余额从下方移入；旧值在动画完成前不得被替换 |
| 错误时仍显示旧余额 | 普通失败会保留 `snapshot.data`；v0.4.4 主胶囊仍显示“查询失败 · 上次余额 ¥X”，v0.4.3 甚至继续将它显示为正常余额 | 当前请求错误优先于历史数据；主胶囊不再显示旧金额，旧金额只能在详情中标为“上次成功余额” |
| 无余额状态不明确 | `isAvailable === false` 仍显示金额；余额列表非空但金额全为 0 也走正常金额分支；402 没有独立映射 | 明确的 402、`isAvailable === false`、空列表或全部币种精确为 0 时，主胶囊统一显示“没有余额”，不显示旧金额 |
| “无法识别”和“没有余额”被混淆 | `UPSTREAM_INVALID_RESPONSE` 也可能是非 JSON、字段类型改变、金额格式异常或响应过大，它不能证明真实余额为 0 | 主胶囊显示“未获取到余额”，详情说明“返回数据无法识别”；不再把旧金额当成当前余额，也不把未知伪造成确定的 0 |
| v0.4.4 实际运行版本无法确认 | `package.json` 是 `0.4.4`，但 `dsh.plugin.json` 仍是 `0.4.3`，该错误已进入 v0.4.4 `.tgz`；项目文档还记录本机真实 profile 仍为 v0.4.3 | 先建立“包内版本→安装后版本→页面运行版本”的可验证链路，再判断动画 |
| 对方电脑双击闪退 | ZIP 内安装器与工作区源码一致，但 `.cmd` 为 LF-only，脚本未强制启用 Command Extensions，括号块中展开未安全的路径变量，并只依赖 `pause` 保持窗口 | 改成“极简启动器 + Node 主安装器 + 持久日志”，不再用 200 多行批处理承载全部逻辑 |

## 2. 证据边界

### 2.1 已确认

- `src/client.js` 的 `end` 阶段会将顶部旧值提前替换为最终值，导致两排文本相同，这是 v0.4.4 动画不可见的确定性实现缺陷。
- 33 项测试没有真正渲染并驱动 `RollingAmount`；现有契约测试只检查源码中是否存在 transition/阶段文本，所以“33 项通过”不能证明动画可见。
- 用户描述的“主标签显示余额，悬停才看到无法识别”与 v0.4.3 客户端行为一致；与当前 v0.4.4 工作区的“查询失败 · 上次余额”行为不一致。
- `package.json`/`dsh.plugin.json` 版本不一致，并且 v0.4.4 包内的 `dsh.plugin.json` 仍为 0.4.3。
- 工作区安装器、`release\dsh-deepseek-balance-0.4.4` 中的安装器与 ZIP 内安装器字节一致；因此本轮不能用“ZIP 装进了另一份新脚本”解释闪退。
- 交付的安装器和诊断脚本都是 LF-only，现有测试没有检查 CRLF。
- 在真实 `cmd.exe /e:off` 模式下，当前安装器会在到达任何 `pause` 之前语法失败；该分支已可复现。
- 在括号块中展开包含 `(1)` 的路径会报 `was unexpected at this time`并退出；对方若解压到浏览器/聊天软件自动生成的“文件夹 (1)”，就符合“本机正常、别人闪退”的差异。
- `pause` 在标准输入关闭时可以立即返回，因此它不是“一定不闪退”的保证。

### 2.2 尚未确认

- 未读取或修改用户/对方的真实 DSH profile，因此不把对方最终加载的版本写成已知事实。
- 尚未拿到对方执行文件的 ZIP SHA256、解压目录名或持久日志，所以“路径括号”和“Command Extensions 关闭”是已复现的闪退路径，但不宣称它们是对方那一次的唯一根因。
- `UPSTREAM_INVALID_RESPONSE` 只证明本次响应未通过校验，没有当时的安全形状记录，不能确定是哪个字段异常。
- `dsh.plugin.json` 版本漂移会使运行版本难以确认，但在隔离 profile 复验前，不断言 DSH 一定以该字段作为客户端缓存键。

## 3. 余额显示状态机

主胶囊、状态颜色、tooltip 和 aria-label 必须由同一个纯状态派生，不再分别拼接。优先级如下：

| 当前状态 | 主胶囊 | 历史金额 | 动画 |
| --- | --- | --- | --- |
| Key 缺失/鉴权失败 | “设置余额”/“Key 无效” | 清空 | 不播放 |
| 首次查询中 | “正在查询” | 无 | 不播放 |
| 已有成功结果，正在刷新 | 保持上次成功值并显示刷新标识 | 详情写“正在更新” | 等结果后决定 |
| `UPSTREAM_INVALID_RESPONSE` | “未获取到余额” | 只在详情显示“上次成功余额/时间”，不写“账户可用” | 不播放 |
| 超时/网络/限流/上游故障 | “余额查询失败” | 同上 | 不播放 |
| HTTP 402 | “没有余额” | 可在详情显示上次成功值，但不得当成当前值 | 可从旧金额滚到“没有余额” |
| 成功响应，但 `isAvailable === false` | “没有余额” | 详情可写“账面剩余 ¥X，当前不可用” | 同上 |
| 成功响应，列表为空或全部金额精确为 0 | “没有余额” | 不显示旧金额 | 可从旧金额滚到“没有余额” |
| 成功且存在可用非零余额 | 当前精确金额 | 不需要 | 与上一次可比成功结果不同时播放 |

补充规则：

1. HTTP 402 增加独立安全错误码，不再与通用上游故障合并。
2. “无法识别”的安全诊断只记录失败阶段（HTTP/内容类型/JSON/结构/金额格式），不记录 API Key、Authorization 或完整上游响应。
3. 判定“全部为 0”继续使用精确十进制字符串逻辑，不转浮点数。
4. 历史数据仍可保留以便解释，但永远不能在当前错误状态下伪装成当前余额。

## 4. 手机时间选择器式余额滚筒

本方案将用户的类比落成为：**把整个“刷新前余额”视为时间选择器的上一项，把整个“刷新后余额”视为下一项**。它不从旧值逐步计数到新值，也不制造中间金额。

视觉与状态规则：

1. viewport 始终存在，高度为一行，隐藏上下溢出。
2. 余额减少时：旧值在上排，新值在下排；轨道向上滚动一行，旧值移出，新值从下方进入。
3. 余额增加时：新值在上排，旧值在下排；轨道向下滚动一行。
4. 时长以 650ms 为基准，使用明显但不拖沓的 ease-out。实现优先使用 Web Animations API 的显式关键帧；CSS transition 仅作为不支持时的后备。
5. 旧值在动画的整个 active 阶段保持不变；只有动画的 `finished`/取消收尾完成后，才把两排同步为最终值并无动画复位。
6. 快速连续刷新时取消旧动画，用“最后一次已显示的结果 → 最新成功结果”重新播放，最新结果永远获胜。
7. 首次加载、金额不变、响应失败、币种不可比、Key 切换不播放数字动画。明确从有余额变为“没有余额”可播放一次文本滚入。
8. `prefers-reduced-motion: reduce` 时立即显示最终结果，不进行位移。
9. 无障碍节点只公布最终余额，不重复读出两排视觉副本。

## 5. 版本真值与安装可验证性

0.4.5 必须以 `package.json.version` 为唯一版本源，并在构建/打包前生成或校验其他位置：

- `dsh.plugin.json.version` 必须与 `package.json.version` 完全一致。
- `.tgz` 文件名、包内两份 manifest、安装器期望版本、ZIP 文件名必须一致。
- 打包后必须解包回读版本、客户端文件 SHA256 和清单，不只校验源码。
- 安装成功后从目标临时 profile 回读实际安装版本和客户端哈希，写入安装日志。
- 余额详情末尾显示非敏感的“插件版本 0.4.5”，用于判断页面是否仍加载旧 bundle。
- 同一版本号的 ZIP 不重复打包和分发。开发中间产物使用构建 ID；对外验收每个版本只有一个确定 SHA256。

## 6. 不闪退的安装器方案

### 6.1 结构

分享 ZIP 中采用三层：

1. `安装 DeepSeek 余额插件.cmd`：极简 ASCII + CRLF 启动器，只用系统 `cmd.exe /d /e:on /v:off /k` 打开主安装器。`/k` 保证即使主安装器语法错误或标准输入关闭，窗口仍然保留，不再把 `pause` 当成保活机制。
2. `install-core.cmd`：仅做 Node 绝对路径定位和启动，首行显式使用 `setlocal EnableExtensions DisableDelayedExpansion`，不在括号块里展开用户路径。
3. `install.mjs`：主逻辑改由 Node 处理，包括文件查找、SHA256、版本、子进程参数、pnpm 引导、阶段日志和退出码。不再让 `cmd.exe` 解析含空格、括号、`&` 或 `!` 的复杂路径。

### 6.2 pnpm 引导

- 已有可用 pnpm 时直接复用，不下载。
- 缺少 pnpm 时，先显示固定版本 `pnpm@11.19.0`、唯一网络地址 `https://registry.npmjs.org/` 和本地目标，只有用户选择 `Y` 才联网。
- 不再执行全局 `npm install --global`。改为安装到插件安装器自己的用户级工具目录，只将其 `node_modules\.bin` 加入本次子进程 PATH。这避免管理员权限、全局 npm prefix 不同和新窗口 PATH 未刷新。
- 用户选择 `N`、网络失败或 npm 返回非 0 时立即停止安装，窗口与日志保留，不自动切换 registry，不自动重试。
- 插件 `.tgz` 仍使用本地文件；不将 API Key 传给 npm/pnpm/npx，不读取 credentials。

### 6.3 日志与解压边界

- 主安装器从第一阶段开始在解压目录写入 `install.log`，记录构建 ID、阶段、工具版本、安全的路径存在性、子进程退出码和安装后版本。
- 日志不记录 API Key、Authorization、credentials 内容、完整环境变量或完整上游响应。
- 若用户直接在 ZIP 预览里双击，启动器检测到同目录文件不完整后，只提示“先完整解压”并保持窗口，不尝试从压缩软件临时目录安装。
- 如果连 `install.log` 都没有生成，则问题位于启动器之前（例如 SmartScreen、安全软件拦截或未完整解压），而不再让用户凭“闪退”猜测。

### 6.4 可重现交付

- 新增唯一发布组装脚本，同时生成 `.tgz`、sidecar SHA256、CRLF 安装器、诊断文件、`MANIFEST.json` 和最终 ZIP。
- `MANIFEST.json` 记录版本、构建 ID、包内文件长度与 SHA256。生成 ZIP 后必须回读所有 entry 并再次比对。
- 测试不再只检查工作区文本，而是执行最终 ZIP 中的启动器/主安装器矩阵。

- 页面详情明确显示运行版本 0.4.5，且运行 bundle SHA256 与 `.tgz` 内一致。
