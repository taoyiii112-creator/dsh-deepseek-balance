# v0.5.8 余额胶囊滚动动画终态修复方案

> **v1.0.1 当前行为：** 余额滚动动画仍遵循系统“减少动态效果”；桌宠动画和本地导入视频也遵循该设置，Wallpaper Engine Video 不受其影响。页面隐藏时页面层背景暂停，设置打开时同一精确来源共用单层并继续播放，来源不同时暂停页面层视频。本文的滚动终态修复沿用至当前版本；整体规则见 [v1.0.1 Desktop 兼容说明](v1.0.1-Desktop兼容说明.md)。

## 现象与根因

余额滚动结束后没有稳定显示新金额，视觉上像停在中间或卡住。当前 WAAPI 动画设置了 `fill: 'forwards'`；`finished` 收尾只清空了 `animationRef` 并更新 React 状态，没有取消已结束的动画。浏览器会继续应用其最后关键帧；React 同时将双行轨道收成单行，动画残留的位移可能把最终金额移出裁剪窗口。

只读回读到本机官方 `web` profile 的 package 与 plugin manifest 均为 0.5.6，其客户端仍使用上述收尾逻辑。工作区源码为 0.5.7。

## 修复方案

1. 动画正常结束时，先把轨道内联位移设为该方向的终点，再取消当前 WAAPI 动画以清掉 `fill: 'forwards'` 效果，最后提交 inactive 状态让 React 只渲染最终金额。
2. 保持旧动画取消与 revision 身份检查；过期的 `finished` 回调不得收尾新动画。CSS fallback、650ms 时长、方向和 `prefers-reduced-motion` 行为保持不变。
3. 双 manifest、README、INSTALL、源码和唯一离线安装 ZIP 更新到 0.5.8；只生成安装包，不更改真实 profile，也不发布 GitHub Release。

## 验收边界

- `npm run lint`、`npm run build` 通过；不运行自动测试。
- 确认两个 manifest、客户端 bundle 与归档版本一致；ZIP 清单中的大小和 SHA-256 全部匹配，0.5.8 仅一份安装 ZIP。
- 安装后的真实 Chromium/Harness 页面需要观察一次扣款和一次增加动画，并确认结束后稳定停在新余额；本轮未获安装要求，不把源码/打包检查表述为真实页面验收。
