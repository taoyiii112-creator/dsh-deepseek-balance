# v0.6.2 DeepSeek Harness Desktop 兼容说明

> **历史版本档案：** 本文记录 0.6.2 版本的兼容边界与当时构建状态。该版本安装包已清理；当前源码和唯一保留的本地安装包为 v1.0.1。以 [v1.0.1 Desktop 兼容说明](v1.0.1-Desktop兼容说明.md) 为准。

## 运行方式

v0.6.2 是普通 DeepSeek Harness 插件，`client.platform` 仍为 `web`，安装到官方 Desktop 主应用管理的 profile。使用者不需要下载 DeepSeek Harness 源码、安装自定义 Shell 或替换官方应用。

Wallpaper Engine 五种类型按来源处理：

- Image：使用项目原始图片；
- Video：使用项目原始 MP4/WebM，通过 Range 读取；
- Scene、Web、Application：Host 校验已安装项目和 WPE 路径，再用官方 WPE CLI 打开带随机后缀的 `DSH Balance` 窗口。Scene 优先使用 `project.json`；若清单缺失、结构损坏或 Scene 入口文件不存在，只在根目录存在唯一 `.pkg` 和 preview 时直接打开 `.pkg`，不解包。Web 使用项目入口 HTML；Application 会在 `type` 缺失时按 `.exe` 项目文件识别，要求每次确认后由 WPE 加载项目清单。插件打开本机配对页，用户在最新版 Chrome/Edge 的窗口选择器中选择该窗口；视频流通过仅本机 ICE 的 WebRTC 返回插件。

设置面板可拖动，屏幕边缘箭头入口已移除；Wallpaper Engine 壁纸从独立选择页挑选。Image 使用验证到的项目原图，Video 详情播放原视频；Scene/Web/Application 的列表预览只用于识别，应用后显示 WPE 实时画面。没有原图时不会把小预览图当作 Image 原图应用。

当页面和设置面板选择同一精确来源时，页面层保持铺满整个窗口且只创建一个媒体/捕获节点；设置卡片叠加约 94% 不透明的深色玻璃底，保留少量底层画面，不单独裁切或播放第二份视频。打开设置时同一 Wallpaper Engine 背景继续播放，页面遮罩最多为 18%。页面与面板来源不同时仍显示各自选择的背景，卡片使用约 82% 深色底，并按既有策略暂停页面层视频。Wallpaper 选择列表用描边表示当前查看项、用“当前使用”标记已应用项；每次打开页面都会清除上次未应用的临时选择。

错误提示区分源文件不可用、WPE 窗口启动失败、系统默认浏览器配对页启动失败、浏览器未完成配对、捕获超时及 WebRTC 连接失败，也分别区分非 Windows Host、Desktop/Host 来源校验失败和插件页缺少 WebRTC 接收接口。官方 Desktop renderer 使用 `dsh-app://app`；Desktop 转发至 Host 时会剥离 Host、Origin、Sec-Fetch-Site，因此客户端仅在已知 Desktop origin 下附带精确的 `x-dsh-wallpaper-renderer-origin` 标记，Host 验证该标记和仍可用的 loopback Host/peer。兼容旧版官方 `app://dsh`。捕获页由 Host 的实际 `webServer.port` 另行生成 `http://127.0.0.1:<port>` 地址，不能把自定义协议直接交给 Chrome/Edge。普通 localhost Web 模式继续使用其 loopback origin。插件主页面不再以 `window.isSecureContext` 作为启动条件；安全上下文检查保留在实际调用 `getDisplayMedia()` 的 localhost 配对页。Scene/Web/Application 点击应用后会在选择页显示等待状态；连接进入 failed 时提前结束等待并报出连接错误。WPE 窗口启动失败会尝试关闭本次随机命名窗口；失败时保留当前背景。根据提示检查本机配对页、所选完整窗口名称和 Workshop 项目下载状态。

浏览器捕获页必须在顶层窗口中由用户点击按钮后调用 `getDisplayMedia`。插件不会枚举桌面来源或自动选择目标窗口。用户必须按配对页显示的完整名称选中随机命名的 `DSH Balance` WPE 窗口；如果选错窗口或选中整个屏幕，插件不能从标准浏览器轨道接口验证真实窗口所有者。配对页不会录制或上传流，停止共享/关闭配对页会关闭本次 WPE 窗口。Application 在插件设置中要求逐次勾选信任确认。

捕获请求的 video 约束设置 `cursor: 'never'`。这是浏览器提示；当前实现不会对轨道应用精确约束或检查实际设置/能力。浏览器可能忽略该请求，因此系统鼠标仍可能随窗口画面共享。壁纸内容自行绘制或已烘焙在画面中的指针也不受此设置影响。

## 本机要求

- Windows 上运行的官方 DeepSeek Harness Desktop 和本机 Wallpaper Engine；WPE 必须已经启动。
- Steam 库中存在已下载的 Wallpaper Engine 项目，并已在设置中注册对应库目录。
- 默认浏览器是最新版 Chrome 或 Edge，允许 localhost 安全上下文、窗口捕获和 WebRTC 本机连接。
- DSH 的本机 Host HTTP 服务正在运行；Desktop 配对页使用 `webServer.port` 指向该 loopback Host，普通 Web 本机模式沿用自身 loopback origin。

远程部署的 Harness Web Host 无法读取桌面用户本机文件，不适用于此功能。插件只接受精确的官方 `dsh-app://app` renderer 来源或 loopback HTTP 来源；不信任任意自定义协议。若新版本仍出现本机来源校验失败，应记录 Desktop 版本与错误码，不能把它直接判定为远程部署。浏览器策略禁用捕获、本机浏览器无法访问 Host、WPE CLI 不接受某个项目时，Scene/Web/Application 原生画面不可用；Image/Video/静态预览仍按插件来源合同回退。

## 生命周期与安全边界

Plugin Host 只接受数字 Workshop ID、16 位库标识、固定类型、受限分辨率和 Application 确认标志；它会重新读取项目清单，并确认 Scene 清单、Web 入口 HTML 或 Application EXE 仍位于已注册的 Workshop 项目目录。对 WPE 和默认浏览器的启动都使用固定可执行入口、参数数组和 `shell: false`。本机配对页使用随机 UUID 会话路径、同源请求、无缓存 CSP，并通过 `RTCPeerConnection` 直接协商，不配置 STUN/TURN 服务。配对页每 30 秒发送一次心跳，Host 定时关闭失联的过期会话。

浏览器窗口选择器授予的是用户选定的窗口流。插件无法从标准 `MediaStreamTrack` 读取窗口标题或 PID，因此必须由用户选择显示的 `DSH Balance` 窗口；插件不能验证是否误选其他窗口或整个屏幕。捕获流只请求 `cursor: 'never'`，不验证浏览器是否遵守；浏览器可能继续把系统鼠标合成进共享画面。壁纸项目自身绘制或烘焙到画面中的指针也不受此请求控制。[W3C Screen Capture 约束定义](https://www.w3.org/TR/screen-capture/#constrainable-properties)、[Chromium cursor 约束实现讨论](https://groups.google.com/a/chromium.org/g/feature-media-reviews/c/cOuS8x8rMZY)。不要在不信任的页面上复用捕获页。Application 项目可能运行其项目程序，只有明确信任时才勾选启动确认。
