# v0.5.5 Web 壁纸渲染按钮与面板背景修复方案

> **v1.0.1 当前行为：** 本文记录的旧 Web 页面捕获流程已移除；当前 Scene/Web/Application 使用 Wallpaper Engine 具名窗口，并由用户在本机 Chrome/Edge 配对页授权选择。捕获请求只设置 cursor: 'never'，浏览器可能忽略隐藏鼠标提示。Wallpaper Engine Video 直接播放原文件。详见 [v1.0.1 Desktop 兼容说明](v1.0.1-Desktop兼容说明.md)。

## 现象与诊断

- v0.5.4 的渲染入口只针对 DeepSeek 页面背景；设置面板背景没有“打开渲染窗口”控制，且 `PanelBackground` 只消费静态图片或普通视频。
- 后端通过 `Get-CimInstance Win32_Process` 检查 Wallpaper Engine。当前普通用户诊断环境运行同一条查询返回“拒绝访问”，而 `Get-Process -Name wallpaper64` 能读取到运行中的 `D:\SteamLibrary\steamapps\common\wallpaper_engine\wallpaper64.exe`。现有代码吞掉该查询异常并返回“未运行”，导致渲染接口误报。
- 当前诊断时没有运行 DSH Web 服务，故未调用渲染打开接口，也未触发 Wallpaper Engine 新窗口。

## 实施范围

1. 将运行检测改用普通用户可读取的进程查询，并继续按解析后的可执行文件完整路径匹配，避免把另一份同名程序误认作目标。
2. 为页面背景和面板背景提供相同的实时渲染入口；捕获会话记录目标 surface，只在所选目标中显示视频流。切换或恢复对应背景时关闭插件创建的专属窗口。
3. 将打开中、成功和失败提示显示在渲染控件附近，避免用户点击后看不到接口错误。
4. 更新中英文提示，明确面板/页面目标和每次重新选择窗口的步骤；版本号升至 0.5.5。

当前进度：上述源码改动及双 manifest/README/INSTALL 版本同步、lint/build、唯一 ZIP、profile 更新均已完成。只读回读显示 `web` profile 双 manifest 为 0.5.5，Wallpaper 列表接口为 HTTP 200（28 项中 21 项可实时渲染）。未打开渲染窗口或启动浏览器捕获；真实画面验收待用户在页面中手动选择窗口。

## 浏览器权限边界

浏览器共享窗口通过 `getDisplayMedia` 完成。W3C Screen Capture 规定浏览器每次都必须让用户选择共享的显示表面，且授权不能持久保存；调用还需要用户的临时交互。因此每次重新加载 DeepSeek Web 页面或新开页面后，用户至少仍需点击一次“选择窗口并显示”并确认 Wallpaper Engine 窗口。插件不能静默恢复浏览器捕获。参见 [W3C Screen Capture](https://www.w3.org/TR/screen-capture/)。

## 验收边界

- 源码中普通权限进程检测能识别 Wallpaper Engine，无法识别时界面展示明确错误。
- 页面背景与面板背景均能启动专属 Wallpaper Engine 窗口并显示用户选择的捕获流；静态预览仍作为回退。
- `npm run lint`、`npm run build`、版本与包内文件校验通过；按项目规则不运行自动测试，除非用户要求。
- 不改变 Wallpaper Engine 正在使用的桌面壁纸，不调用全局暂停/停止，不接入 DSH Desktop。
- 当前 DSH Web 服务不在运行；真实浏览器选择、播放画面与 profile 升级状态单独记录，不能由源码构建结果代替。
