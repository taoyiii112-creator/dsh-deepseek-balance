## 1. 基线与目标

本方案以当前已实施并安装的插件 `v0.4.5` 为基线。现有余额状态机、精确十进制比较、650ms 双排滚筒、错误/无余额边界和安装器保持不变。

下一阶段在 DeepSeek Harness 页面内加入一个悬浮的“DeepSeek 鲸鱼娘”桌宠，用角色动作表达余额变化：

- 余额减少：象征性 Token 飞到嘴边，桌宠张嘴吃下、咀嚼并吞咽。
- 余额增加：桌宠看到资源增加，眼睛发亮并流口水。
- 查询期间：桌宠等待、寻找或看向余额区域。
- Key 缺失或查询失败：桌宠表现疑惑或警告，但不得伪装成余额变化。

初版是 Harness 页面内部组件，不是脱离浏览器、始终置顶的 Windows 原生桌宠。系统级桌宠如需开发，必须作为后续独立方案重新确认。

## 2. 已确认的产品决定

1. 桌宠默认悬浮在页面右下侧、会话输入区域上方，桌面端建议显示宽度约 180px，窄屏约 128～144px。
2. 桌宠支持拖动，位置限制在可视区域内，并使用插件自己的本地页面设置保存位置；不得保存 API Key、余额或用户消息。
3. 桌宠提供关闭/隐藏按钮；隐藏后可从余额胶囊中的小入口重新打开。
4. 现有红色精确扣款差额继续保留。红字负责准确金额，桌宠只负责“资源被吃掉”的语义，两者不互相替代。
5. 桌宠只订阅现有模块级 `balanceStore`，不得增加余额请求、提高刷新频率或复制余额比较算法。
6. Token 数量固定为装饰性视觉元素，不按金额换算。初版每次减少统一显示 3 枚无数字的蓝色 Token 图标，避免暗示精确 Token 消耗。
7. 多币种同一次结果中只要存在 `decrease`，优先播放吃 Token；只有不存在减少且至少存在一个 `increase` 时才播放流口水。
8. 首次成功、金额不变、失败、不可比较币种、Key 切换和无法确认差额的“没有余额”状态，不触发吃 Token 或流口水。

## 3. 最终需要生成的视频：5个

最终动画资源固定为 5 个透明 WebM。制作时可以使用绿幕 MP4 或透明 PNG 帧序列作为中间母版，但安装包以透明 WebM 为主。

| 文件名 | 时长与播放方式 | 角色动作 | 触发条件 |
| --- | --- | --- | --- |
| `idle.webm` | 约 3 秒，无缝循环 | 自然呼吸、低频眨眼、头发与蝴蝶结轻微摆动，保持托腮坐姿 | 无其他事件时 |
| `loading.webm` | 约 2 秒，无缝循环 | 眼睛看向右上方余额区域，轻微抬头，像在等待或寻找 Token | 首次查询或刷新中，且没有更高优先级事件 |
| `eat-token.webm` | 约 1.6～1.8 秒，单次播放 | 视线跟随飞来的 Token，张嘴、咬下、咀嚼、吞咽，最后回到可衔接待机的姿态 | 任一可比较币种余额减少 |
| `drool.webm` | 约 1.6～1.8 秒，单次播放 | 看到资源增加后眼睛发亮、微微前倾、嘴角出现口水，随后收回 | 无减少且至少一个可比较币种增加 |
| `warning.webm` | 约 2 秒，短循环 | 轻微歪头、疑惑或担心；问号等提示由界面绘制，不烘焙文字 | Key 缺失、鉴权失败或余额查询错误 |

除 5 个视频外，每个视频从最能表达该状态的一帧导出同名 PNG 后备图：

- `idle.png`
- `loading.png`
- `eat-token.png`
- `drool.png`
- `warning.png`

因此制作任务是 **5 个视频动作**，不是 10 次独立创作；5 张 PNG 由对应视频关键帧直接导出。

## 4. 为什么 Token 不放进吃动画视频

`eat-token.webm` 只包含角色的观察、张嘴、咀嚼和吞咽，不包含固定位置的 Token 图案。Token 由插件界面单独绘制并根据实时布局运动，原因如下：

- 桌宠可以拖动，嘴部位置会改变。
- 余额胶囊和桌宠在不同屏幕宽度下距离不同。
- 程序可以从余额胶囊中心计算到桌宠嘴部锚点的曲线路径。
- Token 图标可以在减少动态效果模式下替换成静态提示。
- 视频不带固定文字、金额或 Token 数量，后续可复用且不会与真实数据冲突。

正式素材完成后记录 `eat-token` 视频的嘴部锚点比例，例如相对于视频容器的 `x/y` 百分比；插件据此把 3 枚 Token 的终点对准嘴部。

## 5. 两张现有参考图的用途

当前 `桌宠` 目录有两张 PNG：

1. `Codex 图像 2026年9月18日 23_55_31.png`：1536×1024，角色运动与八方向观察说明图。用于保持脸型、发型、服装、饰品、托腮姿态和头部转向一致，不作为运行时素材。
2. `Codex 图像 2026年9月19日 11_00_51.png`：1254×1254，绿色背景角色主图。用于图生视频起始参考、抠像和角色一致性检查；该 PNG 实际没有透明通道，不能直接作为最终透明资源。

两张图都只作为素材母版。公开发布前仍需确认可再分发权利，最终资源不得包含生成平台水印、无权使用的第三方元素或变化后的 DeepSeek 标识。

## 6. 视频制作统一规格

### 6.1 画面规格

- 母版建议：720×720 或更高的正方形画布。
- 插件成品建议：512×512，24 FPS。
- 相机固定，不推拉、不摇移、不旋转画面。
- 人物尺寸、裁切、托腮基准姿势、服装、鲸鱼发夹、蝴蝶结和配色在 5 个视频中保持一致。
- 背景必须为透明；图生视频工具不能直接导出透明时，统一使用纯绿背景制作，再在后期抠像。
- 视频无声音、无字幕、无 UI、无水印，不在画面中写金额或 Token 数量。
- 循环视频首尾姿势、光照和发丝位置应自然闭合；单次视频结尾回到能平滑切回 `idle` 的姿态。

### 6.2 最终格式与体积预算

- 主格式：VP9 WebM，带 Alpha 透明通道，供 Chromium/Harness 使用。
- 后备格式：透明 PNG，分别对应 5 个状态。
- 所有视频总预算建议不超过 8 MiB；单个视频优先控制在 0.6～1.8 MiB。
- 透明边缘不得有明显绿边、白边、锯齿或大面积半透明噪点。
- 帧序列只作为制作和返修母版保存，不默认放进插件 `.tgz`。

### 6.3 推荐制作流程

1. 使用两张现有 PNG 固定角色形象和构图。
2. 分别生成 5 个动作视频，尽量复用同一模型、角色参考、随机种子、镜头和提示词结构。
3. 在 Photoshop/Krita 中修复关键帧的眼睛、手指、发夹、蝴蝶结、服装图案和嘴部一致性。
4. 在 After Effects 或 DaVinci Resolve 中抠绿、清理边缘并检查循环衔接。
5. 导出透明 PNG 帧序列或带 Alpha 的高质量中间文件。
6. 使用 FFmpeg 编码透明 VP9 WebM，并从每个状态导出一张透明后备 PNG。
7. 以透明棋盘格、浅色背景、深色背景分别检查边缘，再测试实际 180px 显示尺寸。

## 7. 页面实现结构

后续代码阶段计划增加独立 `PetOverlay` 组件，但继续复用 v0.4.5 的单一余额状态：

1. 先验证 DSH 是否提供适合全页悬浮内容的稳定插槽或根挂载入口；不在未经验证时直接依赖脆弱的全局 DOM 选择器。
2. 容器使用固定定位，不参与页面布局。外层默认 `pointer-events: none`，仅角色、拖动区和控制按钮恢复可交互，避免挡住会话输入。
3. 同一时间只播放一个角色状态；单次事件视频结束后自动返回 `idle`。
4. 余额刷新中的 `loading` 可以被最新的 `eat-token`、`drool` 或 `warning` 立即替换。
5. 收到更新的 `comparison.revision` 时取消旧事件，只保留最新结果；不得排队播放过期动画。
6. 页面隐藏时暂停视频和粒子，页面恢复后直接回到当前正确状态，不补播历史动画。
7. 资源放入插件明确打包的目录（建议 `client/assets/pet/`），并验证 `.tgz`、ZIP 和离线安装副本都包含相同文件及哈希。

建议的状态优先级：

1. `eat-token`
2. `drool`
3. `warning`
4. `loading`
5. `idle`

## 8. 数据触发规则

| 数据场景 | 桌宠状态 | Token 粒子 |
| --- | --- | --- |
| 首次查询中 | `loading` | 无 |
| 第一次成功建立基准 | `idle` | 无 |
| 可比较余额减少 | `eat-token` | 固定 3 枚，从余额胶囊飞向嘴部 |
| 无减少但存在增加 | `drool` | 无 |
| 余额不变 | `idle` | 无 |
| 普通网络/上游失败 | `warning` | 无 |
| Key 缺失或鉴权失败 | `warning` | 无 |
| 402、不可用、空列表或全零，但无法得到可比较精确差额 | `warning` 或对应静态无余额表现 | 无，不猜测消费 |
| Key 切换或币种结构改变 | `idle` | 无，不跨账号/币种播放 |

余额 API 只提供金额变化，不能可靠推导某次请求的输入/输出 Token 数量。桌宠动画不得显示“消耗了 N Token”一类精确声明。

## 9. 减少动态效果与无障碍

- `prefers-reduced-motion: reduce` 时不播放 WebM 动画、Token 飞行、弹跳或抖动，直接显示对应状态 PNG；短暂状态结束后返回 `idle.png`。
- 桌宠主体属于装饰性反馈，不重复播报余额；精确余额和扣款继续由现有余额胶囊及其无障碍文本负责。
- 关闭、重新显示和拖动控制必须可通过键盘操作，并提供清晰的 `aria-label`。
- 不使用颜色作为唯一状态提示；警告状态同时有姿态/图标含义。
- 用户隐藏桌宠后，不继续在后台播放视频或创建粒子。

## 10. 验收清单

- [ ] 最终共有 5 个透明 WebM 和 5 张对应 PNG，文件名、尺寸、时长、循环属性和哈希有清单。
- [ ] 5 个视频的人脸、眼睛、发型、发夹、蝴蝶结、服装、姿态基准和色调一致。
- [ ] 透明边缘在浅色、深色和 Harness 实际背景上无明显绿边、白边或闪烁。
- [ ] 桌宠默认不遮挡输入框、余额胶囊和会话操作，拖动后不能移出可视区域。
- [ ] 关闭后不播放动画，且可从余额胶囊重新打开。
- [ ] `100.00 → 99.80` 只触发一次吃 Token，3 枚 Token 对准嘴部，红色 `-0.20` 仍准确显示。
- [ ] 余额增加只触发一次流口水，不播放吃 Token。
- [ ] 多币种同时增减时减少优先；首次加载、不变、失败、Key 切换和不可比较结果不误播。
- [ ] 快速连续结果取消旧动画，最终只呈现最新 `revision`。
- [ ] reduced-motion 使用静态状态图，不播放位移或视频。
- [ ] 页面隐藏时停止媒体与粒子，恢复后不补播过期动画。
- [ ] `.tgz`、最终 ZIP 和安装后 profile 均离线加载相同资源，不从外网请求桌宠素材。
- [ ] 自动测试、构建和真实 Chrome `taoyiii` Harness 视觉验收均通过后，才进入版本打包与发布决策。

## 11. 明确不在本阶段实施

- 不开发 Windows 原生始终置顶桌宠。
- 不根据金额猜测精确 Token 数量。
- 不增加声音、语音或联网下载素材。
- 不改变 v0.4.5 已有余额状态机、刷新间隔、Key 安全边界和精确红色差额。
- 本文档阶段不写功能代码、不升级版本、不重打安装包、不修改真实 profile、不发布 GitHub Release。
