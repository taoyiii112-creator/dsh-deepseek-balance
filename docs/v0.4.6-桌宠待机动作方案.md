## 1. 版本结论与本阶段目标

> v0.4.6 是桌宠待机动作的唯一实施与交付版本。v0.4.5 只作为当前已安装基线，不得用 v0.4.5 同名版本重新打包桌宠功能。当前工作区已升级到 0.4.6，但尚未替换真实 profile。

本阶段先完成一个可独立验收的“待机竖切”：让 DeepSeek Harness 页面内出现离线加载的悬浮待机媒体，实现待机循环、静态降级、页面可见性、减少动态效果、拖动和隐藏/恢复边界。其余数据驱动动作仍不在本次代码范围内。

查询、吃 Token、流口水、警告等数据驱动动作继续沿用 [v0.4.5 桌宠互动实现方案](v0.4.5-桌宠互动实现方案.md) 的全量设计，但不进入本次待机竖切，也不得在对应素材和状态接入尚未完成时用待机动作假装这些状态。

文档阶段已结束。本轮已修改 `package.json`、`dsh.plugin.json`、源码、构建脚本和测试，并生成透明素材；未修改真实 DSH profile、未发布 GitHub Release。

## 2. 已确认的待机源素材

历史候选源文件：`桌宠/待机.mp4`（带水印，不进入包）

| 项目 | 已确认结果 |
| --- | --- |
| 文件大小 | 9,949,453 字节，约 9.49 MiB |
| SHA-256 | `843BDA19BC426A29CB9F69D5DA334BC5513B024167782CFD11014DE20ED9B322` |
| 容器与视频编码 | MP4，H.264/AVC（`avc1`） |
| 画面 | 960×960，97 帧，视频轨约 4.0167 秒 |
| 帧率 | 可变帧率，平均约 24.15 FPS；不是严格恒定 24 FPS |
| 音频 | 存在 AAC（`mp4a`）音轨，44.1 kHz，约 4.096 秒 |
| 背景 | 不透明绿幕；当前视频轨没有 Alpha 透明通道 |
| 水印 | 抽查帧右下角均可见“即梦AI”水印 |
| 循环 | 首尾姿态接近但不是无缝同帧，存在明显跳帧风险 |
| 构图 | 发丝、蝴蝶结和手臂靠近边缘，缩放与抠像时存在裁切风险 |
| 动作语义 | 中段闭眼、明显张嘴，可能被理解为打哈欠或唱歌；约每 4 秒重复时可能抢占注意力 |

结论：`待机.mp4` 已完成“源母版到位”这一节点，但尚不是可直接放入插件的最终 `idle.webm`。它不满足透明、无音轨、无水印、无缝循环和体积预算等正式素材门槛。

### 2.1 本次实际采用的用户素材

用户提供的 `桌宠/idle.webm.mp4` 作为无水印待机输入，原文件保留不覆盖。它实际是 H.264/MP4（1920×1080、约 4.033 秒、30 FPS，带 AAC 音轨），因此先裁掉两侧黑边，再抠除绿幕、移除音轨并输出 `桌宠/idle-transparent.webm`。输出为 576×536、30 FPS、VP9 Alpha、无音轨，936,987 字节，SHA-256 为 `58C29C3AC077D5E08FC7A5BCEE5EB7B7A0810F503CCCB19A44C855AAA46DC0B1`。

静态阶段沿用原角色主图 `桌宠/Codex 图像 2026年9月19日 11_00_51.png`，只去除绿幕，输出 `桌宠/idle-static-transparent.png`。输出为 1254×1254 透明 PNG，2,298,154 字节，SHA-256 为 `BE88299623251ED5A695D04F5394FEE704E3AC4CFC4202BBE860939D6F2B9C3B`。

透明预览已在深色背景下核对；VP9 Alpha 通过强制 libvpx-vp9 解码后确认。当前输出暂按 30 FPS、576×536 保留原动作比例，后续若要压到 512×512/24 FPS，应作为独立素材变更重新验收，不覆盖本次成品。

水印不采用后期擦除作为默认处理。进入公开安装包前，必须取得由素材平台合法导出的无水印版本，或换用具备明确再分发权利的无水印母版；同时确认角色造型及 `DeepSeek` 品牌元素的使用边界。

## 4. 待机素材处理链

### 4.1 输入保护

1. 保留 `桌宠/待机.mp4` 作为源母版，不覆盖、不重命名、不直接纳入 `.tgz`。
2. 以本方案记录的 SHA-256 识别本次检查过的输入；母版变化后重新记录大小、时长、轨道和哈希。
3. 先取得可再分发的无水印母版，再开始正式抠像和编码；不得把移除平台水印列为制作步骤。

### 4.2 画面处理

1. 对绿幕建立逐帧 Alpha，清理 H.264 压缩造成的绿色波动、发丝半透明边缘、绿边和闪烁。
2. 在不改变角色比例的前提下缩放并留出安全边距，避免顶部蝴蝶结、左右发丝和底部手臂在 512×512 成品中被裁切。
3. 优先选择角色双眼自然、嘴部中性、姿态最接近首帧的位置作为循环边界；必要时裁切循环点或做极短交叉过渡。
4. 中段明显张嘴动作默认按“低频、不过度抢注意力”原则处理。若无法通过重排/裁切降低重复感，须在实施前由用户确认是否保留该待机语义。
5. 删除完整音轨；即使原音频是静音，也不得把音频轨带进插件资源。
6. 统一为恒定 24 FPS，不保留当前约 24.15 FPS 的可变帧率时间轴。

### 4.3 正式输出

| 文件 | 目标规格 | 用途 |
| --- | --- | --- |
| `client/assets/pet/idle.webm` | 当前 576×536、30 FPS、VP9 Alpha、无音轨、约 4.033 秒 | 正常动态模式 |
| `client/assets/pet/idle.png` | 当前 1254×1254、透明 PNG、原角色主图去绿 | 减少动态效果和视频失败后备 |

体积目标：`idle.webm` 优先控制在 0.6～1.8 MiB；`idle.png` 在不产生明显色带和透明边缘损失的前提下压缩。若待机资源超过 1.8 MiB，必须先说明画质/体积取舍并重新核对全套 5 个动作约 8 MiB 的总预算，不能直接把当前 9.49 MiB MP4 放入插件。

正式资源在进入源码前须记录文件大小和 SHA-256，并在透明棋盘格、浅色背景、深色背景、Harness 实际背景以及约 180px 的真实显示尺寸下验收。

## 5. 待机运行行为

### 5.1 悬浮容器

- 初始位置为页面右下侧、会话输入区域上方；桌面端建议显示宽度约 180px，窄屏约 128～144px。
- 当前实现默认固定在页面右下、输入区上方；拖动时会把位置限制在可视区域内，外层只接收桌宠拖动和隐藏按钮事件。
- 桌宠右上角提供“隐藏桌宠”按钮；隐藏后停止媒体渲染/解码，并在顶栏显示“显示桌宠”恢复按钮。
- 位置和隐藏状态只保存在浏览器本地，不保存 API Key、余额、消息或媒体内容。

### 5.2 播放与降级

- 正常模式加载本地 `idle.webm`，设置 `muted`、`playsInline`、`preload=auto`；视频自然结束后切换静态图，静态图默认展示 15 秒（满足 10–20 秒要求）后重新挂载视频并播放。资源请求由插件自身同源离线路由提供，不访问外网。
- `prefers-reduced-motion: reduce` 时不加载或播放循环视频，直接显示 `idle.png`。
- 页面进入后台或 Harness 页面不可见时暂停视频并暂停静态阶段倒计时；恢复可见后继续剩余静态时间或视频，不制造余额变化事件。
- `idle.webm` 解码、加载或播放失败时切换到 `idle.png`；两者都失败时隐藏桌宠并保留原余额功能，不能让插件顶栏崩溃。
- 同一页面只保留一个桌宠媒体实例；会话切换不得重复创建多个轮询、视频或全局监听器。

### 5.3 本阶段的状态边界

| 页面/余额场景 | v0.4.6 待机竖切行为 |
| --- | --- |
| 页面可见且用户未隐藏 | 播放 `idle.webm`；结束后静态 15 秒，再重新播放 |
| 减少动态效果 | 静态 `idle.png` |
| 页面隐藏 | 暂停视频，不补播 |
| 用户隐藏桌宠 | 停止渲染和媒体解码；顶栏显示恢复按钮 |
| 首次查询或刷新中 | 继续中性待机，不伪装成 `loading` |
| 余额减少或增加 | 继续中性待机，不播放吃 Token/流口水 |
| Key 缺失、无余额或查询失败 | 继续中性待机，不伪装成警告 |
| 待机资源失败 | 静态 PNG；PNG 也失败则隐藏桌宠 |

待后续四类动作素材与状态逻辑实施后，再按全量方案切换优先级。待机竖切不得提前复制余额比较算法或发起新余额请求。

### 5.4 余额阈值与充值链接

- 阈值通过顶栏“阈值”按钮设置，使用非负十进制字符串校验，最多保留 18 位小数；留空并保存表示关闭提醒。
- 阈值只保存在当前浏览器的 `localStorage`，不进入后端、API 请求、日志或插件凭据。多币种时对每个成功余额使用同一个数值阈值，任一余额低于阈值即显示提醒。
- 只有余额查询成功且低于阈值时，余额旁才出现“充值”链接；链接目标固定为 `https://platform.deepseek.com/usage`，由用户点击打开新标签页，插件不得自动跳转。
- 查询失败、未配置 Key、无余额、不可用账户和未设置阈值时不显示充值链接。

## 6. v0.4.6 版本与安装防回归门槛

v0.4.4 曾同时存在两类独立缺陷：包内 `package.json` 为 0.4.4、`dsh.plugin.json` 却仍为 0.4.3；安装器又存在 LF-only、Command Extensions 和特殊路径导致在日志/暂停前退出的问题。v0.4.5 已修复并验证已知路径。v0.4.6 必须保留这些修复，不能仅把文件名改成新版本。

### 6.1 唯一版本链

本次代码阶段已将唯一源 `package.json.version` 升为 `0.4.6`，并保留现有构建校验阻断版本漂移。以下各处必须全部回读为 0.4.6：

1. 工作区 `package.json` 与 `dsh.plugin.json`。
2. 构建后的客户端运行版本。
3. `.tgz` 文件名及包内 `package/package.json`、`package/dsh.plugin.json`。
4. 安装器期望版本、`MANIFEST.json` 和最终 ZIP 文件名。
5. 临时 profile 安装后的 `package.json`、`dsh.plugin.json`、客户端 SHA-256。
6. Harness 页面显示的运行版本与客户端 SHA-256。

任一位置仍为 0.4.5、缺失或互相不一致，构建/安装即判失败，不得生成或发送对外包。

### 6.2 必须验证真实升级，而不只是空目录安装

1. 在临时 `DSH_HOME` 先安装已验收的 v0.4.5 基线。
2. 完整解压最终 `dsh-deepseek-balance-0.4.6-安装包.zip`，直接运行 ZIP 内安装器升级；不得用工作区脚本或 release 目录代替最终包。
3. 不预先卸载 v0.4.5，以验证已安装用户的真实升级路径。
4. 安装退出码必须为 0，日志必须回读 `installedVersion=0.4.6`；profile 中只保留一个活动插件版本。
5. 重启 Harness 后页面必须显示 0.4.6，客户端哈希与最终 `.tgz` 相同；若提示“已是最新”、仍加载 0.4.5 或旧 bundle，验收直接失败。
6. 另做空临时 profile 的全新安装，避免升级成功掩盖首装问题。

### 6.3 安装器不允许退化

- 保留 v0.4.5 的 `/d /e:on /v:off /k` 持久启动器、Node 主安装器、用户级 pnpm、脱敏 `install.log` 和 offline-first 边界。
- 所有 `.cmd` 必须为 ASCII + CRLF；增加字节级测试，明确禁止 lone-LF。
- 安装后除 `package.json` 和客户端哈希外，必须补充回读 `dsh.plugin.json.version`。
- 最终 ZIP 生成后重新解压并逐项核对条目、两份 manifest、插件包 SHA-256 和客户端 SHA-256。
- 中文、空格、`(1)`、`&`、`!` 路径，`cmd /e:off`、stdin EOF、pnpm 的 Y/N、网络失败和工具目录不可写分支必须有明确阶段码、非零退出和持久日志。
- 不覆盖或重打 v0.4.4、v0.4.5 同名包；用户已明确当前没有 v0.4.6 使用者，因此在 v0.4.6 尚未对外分发前允许重组当前候选。v0.4.6 一旦对外分发，后续改变交付物必须使用下一版本号。
