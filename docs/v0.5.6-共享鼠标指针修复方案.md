# v0.5.6 共享鼠标指针修复方案（历史记录）

> **当前状态：** 这份文档记录 v0.5.6 的历史尝试。v0.6.2 后续曾加入轨道精确校验，但用户要求后已回退到 17:47 首轮行为：只请求 `cursor: 'never'`，浏览器可能忽略该请求，系统鼠标仍可能共享。详见 [v0.6.2 本机捕获说明](v0.6.2-官方Desktop本机浏览器壁纸捕获方案.md)。

## 现象与原因

Wallpaper Engine 的专属播放窗口通过浏览器 `getDisplayMedia` 共享到 DeepSeek 页面或设置面板。屏幕捕获默认可能把鼠标指针也绘制进共享视频；用户本地又能看到自己的系统指针，于是画面里出现重复指针。

## 实施方案

1. v0.5.6 当时尝试在初始捕获约束中使用 `cursor: 'never'`。v0.6.2 曾短暂加入轨道精确校验，后按用户要求回退；当前只在请求中设置 `cursor: 'never'`，只捕获用户选中的应用窗口且不请求音频。
2. v0.6.2 的后续轨道精确校验曾在无法确认隐藏时停止共享；该逻辑已按用户要求回退。壁纸内容自身绘制的指针不受 `cursor: 'never'` 请求控制。
3. 将源码、双 manifest、README、INSTALL 和离线安装包版本更新为 0.5.6。保留现有窗口选择、流停止和 Wallpaper Engine 专属窗口清理逻辑。

## 验收边界

- `npm run lint` 与 `npm run build` 通过；不运行自动测试。
- 检查安装包内 manifest、文件哈希和最终唯一 ZIP。
- 只有在真实页面手动选择播放窗口后，才能确认当前浏览器、显卡与捕获 API 实际隐藏指针；构建成功本身不等于完成视觉验收。
- 不改桌面当前壁纸，不启动或停止 Wallpaper Engine，不发布 GitHub Release。
