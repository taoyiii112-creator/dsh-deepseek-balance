## 1. 用户目标

在 DeepSeek Harness 会话顶栏的余额胶囊中：

1. 手动点击余额刷新，或插件每 60 秒自动刷新时，只要余额发生变化，余额数字就播放一次类似里程表/滚轮的纵向切换动画。
2. 动画结束后必须准确停在接口返回的最终余额，不能停在估算值或随机中间值。
3. 如果余额相比上一次成功查询减少，在主余额旁显示更小的红色差额，例如 -1.0。
4. 差额用于帮助用户一眼看出两次刷新之间余额减少了多少，不新增设置页面，也不改变当前顶栏常驻布局。

## 2. 术语与计算口径

- “上次余额”：当前页面生命周期内，上一次成功且可比较的余额查询结果。
- “本次余额”：本次手动或自动刷新成功返回的余额结果。
- “本次扣款”：本次总余额减去上次总余额为负数时的净减少额。
- 比较字段：按币种比较接口中的 totalBalance，不使用充值余额或赠送余额单独推算消费。
- 红色差额只表示两次成功查询之间的净减少，不代表某一次 API 请求的精确费用；这段时间内可能包含多次调用、退款或充值。

## 3. 交互规则

| 场景 | 余额动画 | 红色扣款差额 | 比较基准 |
| --- | --- | --- | --- |
| 第一次成功加载 | 不播放 | 不显示 | 建立首次基准 |
| 余额减少 | 播放一次 | 显示负数，如 -1.0 | 更新为本次余额 |
| 余额增加 | 播放一次 | 不显示红色扣款 | 更新为本次余额 |
| 余额不变 | 不播放 | 清除上一次差额 | 保持/更新为本次余额 |
| 普通网络失败、超时 | 不播放 | 不新增或误报差额 | 不更新最后成功基准 |
| Key 缺失或鉴权失败 | 不播放 | 清除差额 | 重置基准 |
| 通过插件保存新 Key | 下一次成功查询只建立新基准 | 不跨账号显示扣款 | 保存后立即重置基准 |
| 新增或消失某个币种 | 该币种不比较 | 不跨币种显示差额 | 为可用币种重新建立基准 |

手动刷新和自动刷新必须共用同一套比较逻辑，不能出现两套结果或重复触发动画。

## 4. 视觉与动画规格

- 位置：红色差额位于对应主余额右侧、刷新图标之前，保持在同一个顶栏胶囊内。
- 主余额：沿用当前约 12px、加粗的样式。
- 差额：建议 10px、字重 600，明显小于主余额；颜色沿用插件错误红色 #d94b4b。
- 格式：
  - CNY 示例：-¥1.00
  - USD 示例：-$1.00
  - 其他币种示例：-1.00 EUR
  - 小数位优先保持接口当前余额的精度，因此 10.1 → 9.1 显示 -1.0。
- 数字使用等宽数字特性 font-variant-numeric: tabular-nums，避免宽度变化导致顶栏抖动。
- 动画采用“旧金额向上滑出、最终金额从下方滑入”的滚轮效果，建议时长 450–600ms。
- 动画只展示旧余额和最终余额，不生成随机中间金额。
- 动画被新结果打断时，立即取消旧动画，并以最新成功结果为最终值。
- 红色差额保留到下一次成功刷新；如果下一次没有扣款，则清除。自动刷新时最长约保留 60 秒，避免用户错过。
- 页面处于后台或系统启用“减少动态效果”时，直接显示最终余额，不播放滚动，但仍可显示正确的扣款差额。

## 5. 前端状态设计

在现有模块级 balanceStore 中增加以下概念，不增加新的网络请求或轮询器：

- baselineByCurrency：上一次成功余额，按 currency 保存精确金额字符串。
- changeSet：本次成功查询中每个币种的 from、to、delta、kind。
- revision：每次成功结果递增，用于保证同一结果只触发一次动画。
- resetComparison()：保存新 Key、Key 缺失、鉴权失败或账号状态不可比较时重置基准。

成功查询流程：

1. 校验返回数据。
2. 如果不存在可比较基准，只保存基准并显示最终余额。
3. 如果存在基准，按币种计算精确差额并生成 changeSet。
4. 发布新快照，让界面只对发生变化的币种播放动画。
5. 立即把本次成功结果保存为下一次比较基准。

失败查询不得覆盖最后一次成功基准，也不得制造余额动画或红色扣款。

## 6. 精确十进制差额算法

禁止直接用 JavaScript Number 相减，以免出现 -0.999999999 一类浮点误差。

计划实现纯函数：

1. 校验两个金额都是现有接口允许的十进制字符串。
2. 取得两者最大小数位数。
3. 将小数部分补零到相同位数。
4. 去掉小数点并转换为 BigInt。
5. 计算 current - previous。
6. 按原小数位恢复字符串，并格式化币种符号。

示例：

- 10.1 → 9.1：差额精确为 -1.0
- 0.30 → 0.20：差额精确为 -0.10
- 100.00 → 100.00：差额为 0.00，不播放动画

多币种只按相同 currency 独立比较，不允许 CNY 与 USD 相减。

## 7. 组件与实现拆分

计划在客户端实现以下职责：

- 余额比较纯函数：负责金额归一化、精确差额和多币种匹配。
- RollingAmount：只负责旧余额到最终余额的纵向滚动。
- BalanceDelta：负责较小红字、币种格式和无障碍说明。
- balanceStore：统一处理手动刷新、自动刷新、比较基准、变化事件和重置。
- BalancePill：组合主余额、差额、刷新状态和现有设置 Key 对话框。

不引入第三方动画库，优先使用 React 状态和 CSS transform/opacity，保持安装包轻量。

## 8. 无障碍、安全与性能要求

- 支持 prefers-reduced-motion: reduce，直接更新最终数字。
- 滚动中的视觉副本设置为 aria-hidden，屏幕阅读器只读取最终余额。
- 仅在发生扣款时用 aria-live="polite" 播报一次“本次较上次减少 X”，不播报动画中间帧。
- 不能只靠红色表达扣款，文本必须保留负号。
- 不增加轮询频率，仍为页面可见时每 60 秒一次。
- 不新增外部依赖，不向浏览器暴露 API Key、授权头或 DeepSeek 服务端地址。
- 页面卸载时清理动画计时器或 requestAnimationFrame。
- 切换会话时继续复用模块级 store，避免同一次结果在多个会话组件中重复计算扣款。

## 9. 边界说明

- 插件自身保存新 Key 后可以主动重置比较基准，防止把两个账号的余额差当成消费。
- 如果用户在插件外部直接修改凭据，当前 DSH 接口未提供可安全识别账号切换的标识；实现时应在可检测的鉴权状态变化后重置。必要时提示用户刷新页面或重启 Harness 后再建立新基准。
- 账户不可用、余额列表为空或币种结构改变时，不显示推测性扣款。
- 刷新期间继续显示旧余额和加载图标，成功后再播放一次最终变化动画。

- 本版本不设计绿色充值差额；余额增加只播放变化动画。
- 不提高自动刷新频率。
