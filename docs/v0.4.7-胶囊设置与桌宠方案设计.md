## 1. 目标和现状

v0.4.7 的设计目标：用户在余额胶囊旁的齿轮按钮打开插件统一设置，自定义余额自动刷新时间；在同一设置中管理可导入的透明桌宠媒体与最多 3 个自定义桌宠方案。方案可命名、选择封面、保存和切换。

现状核对：v0.4.6 以单个模块级 `balanceStore` 每 60 秒自动刷新，页面隐藏时跳过，回到前台时以 30 秒新鲜度门槛检查；“阈值”是独立按钮。桌宠固定读取打包的 `idle.webm`/`idle.png`，视频自然结束后显示静态图 15 秒；还没有桌宠动作注册表或用户素材存储。余额数字另有 650ms 双排滚筒，不属于本次“动画框架”改动。

## 2. 用户界面

### 2.1 胶囊入口

- 顶栏保持余额主胶囊，点击余额仍手动刷新；在其右侧紧邻放一个齿轮图标按钮，名称为“插件设置”。低余额“充值”仍只在满足阈值时出现。
- 移除顶栏独立“阈值”按钮和独立“显示桌宠”文字按钮；对应操作集中到设置面板中。桌宠隐藏后，设置面板仍能恢复它。
- 移除桌宠本体及其四周的悬浮关闭/隐藏按钮。用户反馈现有关闭入口占据桌宠左下侧的贴边空间；v0.4.7 统一通过胶囊齿轮 → “桌宠” → “显示桌宠”开关来隐藏或恢复。齿轮在桌宠隐藏后仍始终可见。
- 未配置 Key 时，点击余额主胶囊打开设置面板的“余额”页，并定位到 API Key 区；齿轮始终可用。
- 设置面板采用页面内浮层/抽屉，不离开当前会话，不依赖 Harness 全局设置页。顶栏空间不足时，齿轮保留可点击区域，设置面板在可视范围内调整位置。

### 2.2 设置结构

| 区域 | 内容 | 操作结果 |
| --- | --- | --- |
| 余额 | API Key 配置状态与保存入口 | 继续使用服务端 DSH `credentials`；浏览器不回显 Key |
| 余额 | 自动刷新：30 秒、1 分钟、5 分钟、自定义 | 自定义范围 30–300 秒；保存后重排唯一轮询器，默认 1 分钟 |
| 余额 | 余额阈值与充值提醒 | 沿用非负精确十进制输入；充值仍需用户点击 |
| 桌宠 | 显示桌宠开关、当前位置重置 | 开关关闭后立即停止媒体；再次打开恢复此前位置 |
| 桌宠 | 当前方案、方案卡片、导入与编辑 | 内置方案永远可选；用户方案最多保存 3 个 |
| 桌宠 | 场景槽位列表与“添加自定义槽位” | 每个可编辑方案保留 5 个基础槽位，可增加至总计 10 个 |

自定义刷新间隔以秒或分钟输入，范围 **30 秒至 5 分钟（含边界）**，保存前换算为整数毫秒并显示人可读值；允许 45 秒、90 秒、2 分 30 秒等范围内整数秒，不限于预设项。非法值、空值或超范围值不能保存。切换预设或自定义值后立即持久化，下一次自动刷新从保存时重新计时，不额外发起查询；手动刷新仍可用。页面隐藏不发请求，回到前台仅当距上次尝试已达到当前间隔时刷新；正在进行的请求不重复发送。修改间隔不清除上次成功余额、差额基准或 Key。未来如果 DeepSeek 官方要求更高的最小间隔，应以官方限制调整下限。

### 2.3 桌宠贴边与隐藏入口

- 桌宠可拖动到视口左、右、上、下边缘，右侧和底部允许可见像素紧贴边缘；不再为关闭按钮预留外侧空白，也不在边缘出现额外悬浮控件。
- 拖动边界按桌宠实际可见内容的边界计算。内置和导入素材若自带透明空白，应在显示时按透明内容范围调整定位；不得裁掉头发、尾巴或动画关键帧。视频用播放过程的可见范围联合边界，避免帧间抖动。
- 关闭“显示桌宠”开关后，桌宠从页面消失并停止视频/计时；再次打开时恢复最后位置。关闭设置面板后也能通过顶栏齿轮重新进入设置，因此贴边状态下始终有可达的隐藏入口。
- 浏览器窗口缩小后若原位置越界，将可见内容夹回视口；不覆盖输入框的初始位置仍保持原有默认值。桌宠贴边时仍可从可见图像区域拖回页面中央。

### 2.4 方案卡片与封面

- 内置桌宠独立于用户保存名额。最多另外保存 3 个用户方案；达到 3 个时“导入新方案”禁用并说明先删除一个。删除必须在方案详情中明确确认；删除当前方案时自动切换内置方案。
- 每个用户方案有唯一内部 ID、自定义名称（1–24 个字符，去除首尾空白）、封面、媒体槽位和创建/修改时间。允许同名，但卡片仍以封面和内部 ID 区分；建议在 UI 提示重名。
- 封面默认从用户上传的透明静态图取得；也可单独选择一张透明图片。若只上传透明视频，导入流程可从视频抽取静态帧作为封面，并在用户保存前预览；抽帧失败时要求用户选封面，不能使用不透明占位图伪装为素材。
- 卡片显示封面、名称、媒体类型、当前/未选中状态；编辑可改名、换封面、替换媒体，保存后原方案 ID 不变。切换方案不删除原数据，拖动位置和隐藏状态全局保留。

## 3. 桌宠动画框架

这次重构的是桌宠媒体播放与动作选择框架，**不更改余额数字滚筒、红色精确差额和比较算法**。

### 3.1 媒体槽位

每个方案固定保留 5 个基础槽位：“待机”“查询中”“余额减少”“余额增加”“错误”。“待机”必须有一张透明图片或一段透明视频；其余四项可以为空，没有提供的槽位回退到该方案的待机媒体，界面不声称已播放专属动作。**基础槽位即使为空也计入上限。每个可编辑方案最多再添加 5 个自定义槽位，合计不超过 10 个。**内置方案保持只读；要扩展它时，先复制为一个用户方案，复制后的方案也遵守 10 槽位上限。现有 v0.4.6 只交付待机素材，后续四类基础动作仍以既有 v0.4.5 全量方案为制作基线。

状态优先级先保证用户隐藏、页面不可见、减少动态效果和媒体故障的安全边界。可播放时，统一事件分发器同时评估基础槽位和用户保存的触发规则。不同自定义规则同时命中时按用户设置的优先级、再按方案中的排列顺序选出一个；同一时刻只播放一个场景。命中的自定义规则默认替代同事件的基础动作；用户也可选择“基础动作播完后再播”，两者串行且新事件可取消排队的自定义动作。较高优先级的余额错误/变化事件可以中断当前待机或定时场景。同一余额结果只评估一次规则，不重复触发；不可比较币种、首次加载、Key 切换和失败不触发余额增减动作。未配置点击规则时，点击/开始拖动仍重播待机；开始拖动不误触发点击规则。

透明静态图片直接展示，不循环模拟动画；动态图片按资源自身帧播放。透明视频使用静音、行内播放、无控制条；待机视频按“播完 → 封面/静态帧停留 15 秒 → 再播”执行，事件视频只播放一次并回到待机。用户切换方案时销毁旧媒体和对象 URL，重置动作队列，不产生余额事件。减少动态效果模式显示所选方案的静态封面/后备图，停止所有动态媒体与装饰粒子；封面不可用时隐藏桌宠并保留余额功能。

### 3.2 自定义槽位与真正可配置的触发规则

在桌宠方案的“场景槽位”区显示固定的 5 个基础项和 `5/10` 计数。点击“添加自定义槽位”打开空白模板；每保存一个新槽位，计数加 1。达到 `10/10` 时按钮禁用并提示“请先删除一个自定义槽位”。基础槽位不可删除，自定义槽位可改名、替换素材、编辑触发规则或删除；删除当前播放项时立即回到待机。方案数上限 3 与单方案槽位上限 10 相互独立。

| 模板字段 | 用户填写内容 | 规则 |
| --- | --- | --- |
| 场景名称 | 如“挥手”“晚安” | 1–24 字符，同一方案内不可与其他槽位重名；内部 ID 独立于名称 |
| 动作媒体 | 透明视频或透明图片 | 沿用本方案的媒体格式、Alpha 与大小校验；必填 |
| 静态封面/后备 | 透明图片，或从视频抽取的透明帧 | 视频场景必需，用于减少动态效果与解码失败；图片场景可直接复用原图 |
| 触发规则 | 用户选择事件来源并添加条件 | 可为同一槽位添加多条规则；每条规则的条件全部满足才触发，多条规则之间满足任一条即可 |
| 播放控制 | 单次/状态持续、冷却间隔、优先级 | 防止重复播放和多个场景争抢；循环场景必须有明确退出条件 |
| 与基础槽位的关系 | 替代同事件基础动作 / 基础动作播完后再播 | 默认替代，使自定义规则命中时立即生效；串行模式不同时播放两个媒体 |

规则编辑器的“当”从插件已接入的事件来源中选择，“且”增加该事件适用的类型化条件。例如可选择“余额发生可比较的减少”并限定币种、精确差额范围；也可选择“本地时间进入某时段”并限定桌宠处于待机。初版候选事件来源包括余额查询开始/成功/失败、可比较的余额增加/减少/不变、桌宠点击、待机周期/时长、本地时间。每一种事件在实施前都要确认插件确实能可靠观察；未接入的 Harness 聊天事件不得显示为可用选项。条件编辑器只提供对应事件可验证的字段与比较运算，不接受自由执行的脚本。余额条件沿用精确十进制字符串比较，不能引入浮点扣款误报。

每个自定义槽位可保存零条或多条触发规则。零条规则的槽位是草稿，只能在方案编辑页“播放预览”，不会自动播放；“手动预览”因此不是触发方式选项。每条规则可选择播放一次或循环至该事件状态结束，并可设置冷却间隔、同类规则优先级及与同事件基础动作的串行/替代关系。自定义视频单次播放结束后返回待机，静态图片按设置的展示时长结束；循环必须在状态结束、隐藏、方案切换或更高优先级事件到来时退出。若视频无法播放则显示该槽位的静态后备，后备也失败则回到待机。

自定义名称只是场景标签，**不会自动生成新的余额或聊天事件**。这里的“自定义”是用户配置“已接入事件 + 自定条件 + 播放控制”的规则，不再是固定三选一；它也不承诺任意外部事件都能触发。首版不接受用户脚本或外部 URL；例如“收到聊天消息后跳舞”必须先验证并接入 DSH 聊天事件，不能仅靠命名实现。完整可填写范本与示例见 [自定义桌宠槽位模板](v0.4.7-自定义桌宠槽位模板.md)。

### 3.3 导入格式与验证

首版格式白名单：带真实 Alpha 的 VP9 WebM 视频（`.webm`，无音轨）和带真实透明像素的 PNG、WebP、APNG 图片。MP4/H.264 普通视频、不透明 JPG、没有 Alpha 的 WebM/图片、外部 URL、脚本和压缩包均拒绝。Animated WebP/APNG 保留原动画；静态 PNG/WebP 保持静态。GIF 暂不列入首版白名单，因为其 1 位透明、逐帧解码和浏览器验证边界与其他图片不同；如用户需要，可在预览反馈后补入规格。

扩展名与 MIME 只能用于初筛；最终还需读取文件头、确认浏览器可解码，并以像素/Alpha 信息验证透明度。视频逐帧或抽样核查 Alpha，不能只检查容器声称支持透明；至少确认首、中、末帧，无法验证时拒绝并给出明确原因。图片确认存在非全不透明像素。统一限制分辨率、时长和单文件/方案总大小，在实现前根据浏览器存储配额与真实素材试验确定具体数值，超限时提示压缩而不静默裁切。导入只处理用户显式选择的本地文件，不传至 DeepSeek 或任何远程服务。

### 3.4 持久化与资源隔离

- 小型设置（刷新间隔、阈值、选中方案 ID、显示/位置状态）放浏览器本地设置存储；媒体 Blob、封面及方案元数据放 IndexedDB，避免把大型二进制塞进 `localStorage`。这是当前浏览器当前 DSH 来源的本地保存，不自动跨设备同步。清除站点数据会删除用户方案，界面必须明确说明。
- 每次保存先验证全部媒体并估算配额；写入方案与封面采用事务语义，失败不覆盖旧方案。删除后释放对应 Blob；切换/卸载组件时撤销对象 URL，避免残留解码与内存占用。
- 方案媒体仅作为页面内媒体源，不作为可执行代码或 HTML 注入；文本名称按纯文本显示。现有打包素材继续走固定的同源只读资源路由，自定义媒体不通过该路由暴露。
- API Key 继续只由服务端 DSH `credentials` 或环境变量读取；方案数据、设置和导入错误日志均不得包含 Key 或余额响应。自动测试不得调用真实 DeepSeek API。

## 4. 实施拆分与验收

1. 统一设置浮层：入口、键盘/焦点、窄屏布局、Key/阈值/桌宠显隐迁移；原能力保持可达。
2. 刷新调度：单一可重排计时器，持久化间隔，前后台与手动刷新去重；仍复用同一余额请求和精确比较路径。
3. 方案仓库：IndexedDB 事务、最多 3 个用户方案、每方案 5 个基础加最多 5 个自定义槽位、名称/封面编辑、导入验证与配额错误恢复。
4. 桌宠播放器：接入可观察事件目录和类型化条件规则，按优先级、同事件替代关系与播放控制选择媒体；处理静态/视频降级、减少动态效果、对象 URL 生命周期。
5. 版本链：源码与双 manifest、插件包、ZIP、隔离升级均已回读为 0.4.7；页面运行版本、真实 profile 安装与正式发布仍需单独处理。

验收场景至少覆盖：默认 60 秒、30 秒/5 分钟/自定义边界与非法输入（包括 45 秒、90 秒、2 分 30 秒、301 秒）、切换间隔不重复轮询、隐藏/恢复、Key 变化和失败不误报扣款；透明与非透明素材、无音轨检查、损坏文件、存储不足、三方案上限、改名/换封面/替换媒体、删除当前方案回退内置、重载后恢复；基础 5 槽位不可删除且计数、6–10 槽位添加、达到 10 后禁止添加、删除后恢复名额、重名与缺失媒体报错、零规则草稿、多规则“或”与规则内条件“且”、类型不匹配/不可用事件拒绝、精确金额条件、冷却、循环退出、同事件替代与冲突优先级、静态后备和重载后恢复。静态图片与视频播放、页面后台、减少动态效果、媒体失败、快速切换方案和多币种比较边界均需覆盖。浏览器画面验收需核对顶栏拥挤时设置按钮、抽屉遮挡、约 180px 桌宠显示与拖动范围；还要验证桌宠四边贴合、无悬浮关闭按钮、缩窗夹回及从设置开关恢复。

## 5. 本次预览的待确认点

- 设置面板建议用右侧抽屉；若用户更喜欢从齿轮展开紧凑弹窗，可以按预览调整。
- 当前方案卡片按“内置方案 + 最多 3 个自定义方案”呈现；如果“最多 3 个”需要包含内置方案，应在编码前改为总数限制。
- 刷新时间按用户反馈确定为 30 秒至 5 分钟；媒体大小上限待真实素材与浏览器配额验证后确定。
- 图片首版支持 PNG/WebP/APNG；如需要透明 GIF 或其他有 Alpha 的视频编码，请在预览反馈中指定。
- 自定义槽位按“5 个基础 + 最多 5 个新增 = 每方案 10 个”展示；规则编辑器允许选已接入事件并组合条件、冷却、优先级和替代基础动作，不再限制为三个固定播放时机。聊天等新来源须先验证 DSH 能否提供。
