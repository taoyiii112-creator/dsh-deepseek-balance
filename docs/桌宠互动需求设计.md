# 桌宠互动需求设计

> **v1.0.1 当前行为：** 桌宠动画和余额滚动遵循系统“减少动态效果”；本地导入视频也遵循该设置。Wallpaper Engine Video 不受此开关影响；页面隐藏时页面层背景暂停，设置打开时同一精确来源共用单层并继续播放，来源不同时暂停页面层视频。本文保留早期桌宠需求；当前完整边界见 [v1.0.1 Desktop 兼容说明](v1.0.1-Desktop兼容说明.md)。

状态：历史需求基线；全量设计见 v0.4.5 方案，首个待机竖切见 v0.4.6 方案

日期：2026-09-18（2026-09-23 由 v0.4.5 定稿方案接替）

> 本文保留早期需求讨论。5 个动作的完整规则以 [v0.4.5 桌宠互动实现方案](v0.4.5-桌宠互动实现方案.md) 为基线；2026-09-24 起，待机动作优先按 [v0.4.6 桌宠待机动作方案](v0.4.6-桌宠待机动作方案.md) 分阶段推进。

## 1. 目标

在 DeepSeek Harness 的余额插件内增加一个页面内悬浮桌宠，使余额变化具备直观、可爱的资源语义。初版是网页内组件，不是脱离 Harness 的 Windows 原生桌宠；如需系统级常驻窗口，需另行设计和确认。

## 2. 已确认的交互语义

| 余额变化 | 桌宠表现 | 目的 |
| --- | --- | --- |
| 余额减少 | 象征性 Token 从余额区域飞向桌宠嘴边，桌宠张嘴、吃掉、咀嚼或吞咽 | 表达可用 Token/资源正在被消费 |
| 余额增加 | 桌宠看向资源并露出流口水表情 | 表达可用资源增加 |

“吃掉 Token”是余额减少的主要桌宠表现，不使用与资源含义无关的泛化悲伤动作。现有顶栏红色精确差额是金额数据展示；是否继续与桌宠共存，待实现前由用户确认，当前不改变它。

## 3. 数据和触发边界

- 桌宠只复用现有客户端模块级 `balanceStore` 的快照、`loading`、`comparison.changeSet` 和 `revision`，不得发起额外余额请求或改变 60 秒刷新间隔。
- `change.kind === 'decrease'` 时触发吃 Token；若本次没有任何减少而存在 `increase`，触发流口水。多币种同时出现增加和减少时，暂定减少优先，避免两段相互冲突的动画同时播放。
- 余额 API 只提供金额变化，不能可靠换算某次调用的精确 Token 消耗。因此 Token 的数量、飞行速度和大小只能是象征性视觉效果，不得显示为精确 Token 账单。
- 首次成功加载、余额不变、失败、Key 缺失/鉴权失败、不可比较币种和账号切换边界，沿用既有比较规则，不触发吃 Token 或流口水。
- 新结果在桌宠动画期间到达时，应取消或合并旧动画，只保留最新 `revision` 对应的状态；不得堆积大量动画。
- 必须支持 `prefers-reduced-motion: reduce`：直接切换最终表情/静态提示，不播放飞行、咀嚼或流口水动画。

## 4. 建议的状态机

| 状态 | 触发 | 建议表现 |
| --- | --- | --- |
| idle | 无变化、页面可见 | 呼吸、轻微漂浮、低频眨眼 |
| loading | `loading === true` | 观察、等待或寻找 Token |
| eat-token | 存在余额减少 | Token 飞入嘴边，张嘴、咀嚼、吞咽 |
| drool | 无减少且存在余额增加 | 眼睛发亮、看向资源、流口水 |
| warning | Key 缺失或请求失败 | 疑惑/提示状态，不伪装成余额变化 |

桌宠应提供关闭/隐藏入口，支持拖动或固定到边角，并确保除桌宠可交互区域外使用 `pointer-events: none`，不遮挡会话输入框、余额胶囊或原有按钮。

## 5. 素材规范与制作流程

当前 `桌宠` 目录中的 JPG 是白底静态参考图，MP4 是绿幕且带水印的参考视频。它们不能直接作为公开发布的最终资源：发布前必须确认再分发授权，不能把去除水印作为默认流程。

建议的成品资源：

- `idle.webm`：透明背景、2～3 秒循环；
- `eat-token.webm`：透明背景、约 1～1.5 秒；
- `drool.webm`：透明背景、约 1.5～2 秒；
- `fallback.png`：透明静态后备图；
- 可选的透明 PNG/WebP 帧序列：仅作为制作母版或逐帧控制的备选。

推荐流程：先以分层 PSD/透明 PNG 准备头发、眼睛、嘴、手臂和身体；使用 Photoshop/Krita 做修图和分层，After Effects、DaVinci Resolve 或 Live2D Cubism 制作动作；以 15～24 FPS 导出透明帧序列作为母版，最后编码为带透明通道的 WebM。帧序列不是最终包的首选，因为完整 PNG 序列会显著增加离线安装包体积。

## 6. 技术集成边界

- 先验证 DSH 中适合页面悬浮组件的稳定挂载入口；不在未经验证的情况下依赖脆弱的全局 DOM 注入。
- 素材须被明确列入 npm 包的 `files` 清单，并使用固定、同源、只读的资源路径或受控静态路由提供；当前根目录 `桌宠` 文件夹不会自动进入 `.tgz`。
- 桌宠组件应订阅同一份 `balanceStore`，不复制比较算法、不保存 API Key、不访问 DeepSeek 上游接口。
- 客户端源文件是 `src/client.js`，`client/client.js` 是构建产物；后续只编辑源文件并通过现有构建流程生成产物。

## 7. 验收方向

- 余额减少时，只播放一次吃 Token，最终余额和现有精确差额保持正确。
- 余额增加时，只播放一次流口水；不把充值误展示为 Token 消耗。
- 页面窄屏、输入框操作、会话切换、连续刷新和多币种变化时，不遮挡关键操作，不重复请求，不堆积动画。
- 减少动态效果模式没有运动动画，但状态含义仍可理解。
- 离线安装后的 `.tgz` 包内包含桌宠资源；无网络时能加载后备图或动画。
- 公开发布的素材具备明确授权且不含未经许可处理的水印。

## 8. 待确认事项

1. 桌宠是仅在 Harness 页面内悬浮，还是将来需要独立的 Windows 系统级窗口。
2. 现有红色精确扣款差额是否保留，与吃 Token 动画共存，还是在桌宠版本中隐藏。
3. 最终使用原创分层角色、已授权视频转透明动画，还是重新生成可公开分发的素材。
